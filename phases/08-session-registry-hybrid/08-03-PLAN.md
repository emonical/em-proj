    test_killed_child_excluded_and_reaped():
      TEST-03 point 3: register child → kill its pid → assert next list excludes it and DELs key.
      This is the core stale-reaping proof (D2/D3).

      Approach: spawn a long-running child process that (1) registers itself, (2) idles.
      We record its pid from the register output, then kill it, then call list and assert exclusion.

      Implementation:
      - Use subprocess.Popen([EM_PROJ_BIN, "session", "register", "--json"], env=child_env) to register
      - Parse stdout to get session_id and pid from register output
      - Separately spawn a long-running subprocess (e.g. sleep 60) with the SAME CLAUDE_CODE_SESSION_ID
        so its pid is live while we assert the session is registered — wait, the "pid" in the session
        record IS the pid of the process that ran `session register`, not the sleeping process.

      ALTERNATIVE (cleaner): Instead of needing a live process, use the is_holder_stale path directly:
      - Register a session by running `em-proj session register --json` → get session dict including pid
      - Confirm it appears in list
      - The register command's child process exits normally after registering (pid is now dead)
      - The registered session's pid is therefore already dead (the register process exited)
      - Call em-proj session list --json again
      - The session for that unique_id should be EXCLUDED (pid dead → is_holder_stale → reap)
      - Assert the unique_id is NOT in the list output
      - Verify Redis key DELed: use redis.Redis(db=TEST_DB).exists("state:session:" + unique_id) == 0

      This approach works because `session register --json` is a short-lived process — after it exits,
      the registered pid is dead. The next `session list` will detect it as stale and reap it.
      This is the canonical lazy-reaping path.

    test_ttl_lapse_session_absent_from_list():
      TEST-03 point 4: a session whose Redis TTL has lapsed is absent from list.
      This proves the TTL backstop (D2).

      Approach: register a session, then directly manipulate the Redis key's TTL via the test's
      redis client (db=15) to set it to 1 second, then wait 2 seconds, then call list.
      Assert the session is absent (key expired → HGETALL returns empty → skipped by list).

      Implementation:
      - Generate unique_id; run register → exit 0
      - Connect to Redis(db=TEST_DB); client.expire("state:session:" + unique_id, 1)  (set TTL to 1s)

      - Run em-proj session list --json
      - Assert unique_id NOT in list data (key gone)
      NOTE: do NOT wait 300 seconds — use Redis client to force-expire the key via EXPIRE 1.
