<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → session_register() | session_id comes from env var (CLAUDE_CODE_SESSION_ID); no caller-supplied session_id parameter — identity.py resolves it |
| session_list/show → Redis HASH | raw HGETALL dict decoded; malformed entries skipped (try/except) |
| _scan_all_holders_by_session_id → claim/lock/reserve namespaces | reads foreign HASH/JSON; malformed entries skipped; stale holders excluded via is_holder_stale |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01-01 | Spoofing | session_register: session_id identity | accept | session_id comes from CLAUDE_CODE_SESSION_ID (env var set by Claude Code); same trust model as v1.0 claim/lock; no session_id forgery concern in single-user context |
| T-08-01-02 | Tampering | Redis HASH fields for session record | mitigate | _hgetall_to_session validates field types (int/float coercion); missing required fields raise KeyError → entry skipped; no unauthenticated Redis write path in single-user local setup |
| T-08-01-03 | Information Disclosure | _scan_all_holders_by_session_id reads all claim/lock/reserve keys | accept | machine-global registry is the stated design (D4); all data is locally-owned; no PII or secrets in holder records |
| T-08-01-04 | Denial of Service | unbounded scan_iter over state:session:* | mitigate | count=100 cursor batching (same pattern as claim_list_by_prefix); stale entries reaped on read, keeping keyspace bounded by active sessions |
| T-08-01-05 | Elevation of Privilege | lazy DEL of stale session keys | accept | DEL is scoped to state:session:<session_id> keys; no Lua required for delete (not a compare-and-delete — any reader may reap a verifiably stale entry); race between two reapers results in one DEL and one no-op (Redis DEL on missing key is safe) |
</threat_model>
