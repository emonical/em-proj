<!-- The em-proj state claim CLI contract (already shipped in Phase 4) -->

Invocation:
  em-proj state claim [--ttl <secs>] [--json] <area>

Behavior:
  - Reads CLAUDE_CODE_SESSION_ID from env (required; refuses anonymous claims)
  - Computes project_hash from cwd via tr '/' '-' on absolute path
  - Atomically refreshes-or-takes the claim via Lua LUA_CLAIM_REFRESH_OR_TAKE
  - --json mode: emits {"schema_version":"1","status":"ok","data":{...}} on stdout
  - --ttl: integer seconds; default 1800 (30min)

Exit codes:
  0 = taken or refreshed (the caller now holds the claim)
  1 = error (e.g. anonymous claim refused, Redis unreachable, invalid area name)
  3 = held by another session (data.holder contains {session_id, project_hash,
      reason, claimed_at, expires_at})

Stdout shape on exit 0 (taken/refreshed):
  {"schema_version":"1","status":"ok","data":{"area":"workstream.active",
   "ttl":1800,"claimed_at":"<iso>","expires_at":"<iso>","action":"taken"|"refreshed"}}

Stdout shape on exit 3 (held_by_another):
  {"schema_version":"1","status":"held_by_another","data":{"holder":{...}}}
  (CLI emits to stdout in --json mode; verify exact shape during execution by
  reading src/em_proj/state/__init__.py:439-505 and tests/multiprocess/test_claim_race.py:159-179)
