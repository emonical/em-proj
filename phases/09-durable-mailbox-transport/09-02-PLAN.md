<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → mbox_write | session_id is caller-supplied; msg dict is caller-supplied; body and other fields must be validated |
| caller → mailbox_inbox | session_id is caller-supplied; since is caller-supplied and passed as XRANGE min — must not allow injection |
| _ops.py → Redis | All Redis calls via get_client() singleton; decode_responses=True; connection errors not caught here (D-18 carry) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-02-01 | Tampering | mbox_write: body field length uncapped | mitigate | _validate_body raises ValidationError if len(body) > MAX_BODY_CHARS (4096); same pattern as claim.py MAX_REASON_CHARS; called before any Redis operation |
| T-09-02-02 | Denial of Service | mbox_write: unbounded XADD flooding a session's mailbox | mitigate | XADD maxlen=MBOX_MAXLEN (500) approximate trim on every write; key-level EXPIRE=MBOX_TTL_SECONDS (3600) auto-expires the whole mailbox for dead sessions; MAXLEN is the hard(ish) bound — approximate trim may allow ~10% overage |
| T-09-02-03 | Denial of Service | mailbox_inbox: MINID trim passes cutoff_id derived from system clock | accept | Uses time.time() which is machine-local; clock skew is a cosmetic issue (entries survive slightly longer than TTL); MAXLEN trim is the binding bound; per Pitfall 2 in research |
| T-09-02-04 | Spoofing | mbox_write: from_session field is caller-supplied (not verified against registry) | accept | Phase 9 mbox_write is a pure write primitive; Phase 10 send path validates the sender's session is registered before calling mbox_write; machine-local single-user context; no cross-user threat |
| T-09-02-05 | Tampering | mailbox_inbox: since=<id> passed to XRANGE min; injection via crafted ID string | mitigate | Redis XRANGE min argument is a stream ID (format: <ms>-<seq> or literal '-' or '(' prefix + ID); malformed IDs return empty result or Redis error (not data leak); the '(' prefix is prepended by code, not caller — caller supplies only the bare ID string; validate that since contains only digits and '-' if strict input validation is desired; for Phase 9 this is accepted (machine-local, same-user caller) |
| T-09-02-06 | Information Disclosure | Any session can call mailbox_inbox for any session_id | accept | mailbox key is mbox:<session_id>; trust boundary is machine-local, single-user; authorization check (is caller the owner of session_id?) is a Phase 10 concern; Phase 9 ops are internal primitives called only by the CLI verb which routes via session identity |
</threat_model>
