    Create src/em_proj/state/claim.py following the lock.py module structure:

    MODULE DOCSTRING: Mirror lock.py's docstring structure. Document D-17 (pure ops, no typer), D-18 (get_client() chokepoint), key shape claim:<project_hash>:<area>, Lua atomicity rationale, and the novel refresh semantics (same-holder repeat call extends TTL, does not error).

    CONSTANTS (module-level):
      KEY_PREFIX: str = "state:claim:"
      TTL_DEFAULT: int = 1800   (30 minutes — CLAIM-01)
      MIN_TTL: int = 60         (1 minute minimum; less would behave like a lock)
      MAX_TTL: int = 86400      (24 hours maximum)
      MAX_REASON_CHARS: int = 256   (mirror lock.py)

    KEY SHAPE: claim key is KEY_PREFIX + project_hash + ":" + area
      Full key: "state:claim:<project_hash>:<area>"
      This is different from lock.py (which has no project_hash in the key) because
      claims are inherently project-scoped while locks are user-global.

    HOLDER RECORD (5 fields, CLAIM-02):
      {session_id, project_hash, reason, claimed_at, expires_at}
      All are stored in a Redis HASH (HSET/HGETALL) rather than a single JSON string.
      RATIONALE: Lock.py uses a single JSON string to enable byte-stable Lua comparison
      (LUA_COMPARE_AND_SWAP_IF_STALE needs exact byte match). Claims do NOT need that
      stale-takeover script; refresh is same-holder only. Using a Redis HASH makes
      individual field updates (refresh: just update expires_at) simpler and Lua cleaner.
      Store numeric fields (claimed_at, expires_at) as floats; reason as string or "".

    EXCEPTIONS:
      HeldByAnother(holder: dict | None, message: str | None) — exact same shape as lock.py.
        code = "held_by_another"
      ClaimNotHeld(message: str | None) — new exception, raised by claim_check when absent.
        code = "not_held"

    LUA SCRIPTS (three scripts, each a module-level string constant):

      LUA_CLAIM_REFRESH_OR_TAKE:
        KEYS[1] = full Redis key (state:claim:<project_hash>:<area>)
        ARGV[1] = session_id (caller's)
        ARGV[2] = project_hash (caller's)
        ARGV[3] = reason (string or "")
        ARGV[4] = claimed_at (float as string)
        ARGV[5] = expires_at (float as string)
        ARGV[6] = ttl (int as string, for EXPIRE)

        Logic:
          1. Check if key exists (EXISTS KEYS[1])
          2. If absent: HSET all 5 fields + EXPIRE ttl → return "taken"
          3. If present: read HGET KEYS[1] "session_id" and HGET KEYS[1] "project_hash"
          4. If session_id AND project_hash match caller (ARGV[1], ARGV[2]):
             HSET KEYS[1] "expires_at" ARGV[5] + EXPIRE KEYS[1] ARGV[6] → return "refreshed"
          5. Else: return "conflict" (caller reads existing holder via HGETALL)

      LUA_CLAIM_COMPARE_AND_DELETE:
        KEYS[1] = full Redis key
        ARGV[1] = session_id (caller's)
        ARGV[2] = project_hash (caller's)

        Logic:
          1. Check if key exists: if absent return -1
          2. HGET KEYS[1] "session_id" and HGET KEYS[1] "project_hash"
          3. If both match: DEL KEYS[1] → return 1
          4. Else: return 0 (mismatch — different holder)

      LUA_CLAIM_CHECK:
        KEYS[1] = full Redis key
        No ARGV.
        Returns: HGETALL result (as Lua table → Redis bulk reply) or false if absent.
        This is a read-only Lua script; it doesn't modify state. Exists so the
        "check if exists + read all fields" is atomic (no TOCTOU between EXISTS and HGETALL).

    PRIVATE HELPERS:
      _build_redis_key(project_hash: str, area: str) -> str
        Returns KEY_PREFIX + project_hash + ":" + area
      _make_holder(area: str, reason: str | None, ttl: int) -> dict
        Calls resolve_session_id() and resolve_project_hash() from identity.py.
        Returns {session_id, project_hash, reason, claimed_at, expires_at}
        where claimed_at = time.time() and expires_at = claimed_at + ttl.
      _hgetall_to_holder(raw: dict) -> dict
        Converts Redis HGETALL string-string dict to typed holder dict:
          claimed_at → float(raw["claimed_at"])
          expires_at → float(raw["expires_at"])
          reason → raw.get("reason") or None (empty string → None)
      _validate_reason(reason: str | None) -> None  (mirror lock.py)
      _validate_ttl(ttl: int) -> None               (mirror lock.py using claim TTL bounds)

    PUBLIC FUNCTIONS:

      claim_take(area: str, ttl: int = TTL_DEFAULT, reason: str | None = None) -> dict
        1. validate_key(area) (same Phase 2 validation — import from kv.py)
        2. _validate_reason(reason)
        3. _validate_ttl(ttl)
        4. Build holder via _make_holder(area, reason, ttl)
        5. Build redis_key via _build_redis_key(holder["project_hash"], area)
        6. EVAL LUA_CLAIM_REFRESH_OR_TAKE with all ARGV values
        7. If result == "taken": return holder
        8. If result == "refreshed": read back via HGETALL, return updated holder
           NOTE: do NOT use the locally-built holder for "refreshed" — the Redis
           value is authoritative (another process may have set claimed_at earlier).
        9. If result == "conflict": HGETALL the existing holder, call _hgetall_to_holder,
           raise HeldByAnother(holder=existing)
        Raises: ValidationError (name/reason/ttl), HeldByAnother (conflict)

      claim_release(area: str) -> None
        1. validate_key(area)
        2. resolve project_hash and session_id via resolve_project_hash() / resolve_session_id()
        3. Build redis_key
        4. EVAL LUA_CLAIM_COMPARE_AND_DELETE
        5. result == 1: return (success)
        6. result == -1: raise HeldByAnother(holder=None, message="claim not held (may have expired)")
        7. result == 0: HGETALL current holder, raise HeldByAnother(holder=current)
        Raises: ValidationError, HeldByAnother

      claim_check(area: str) -> dict
        1. validate_key(area)
        2. resolve project_hash
        3. Build redis_key
        4. EVAL LUA_CLAIM_CHECK
        5. If absent (Lua returned false / nil): raise ClaimNotHeld(message=f"area '{area}' is not claimed")
        6. Convert HGETALL result to holder via _hgetall_to_holder
        7. Return holder dict
        Raises: ValidationError, ClaimNotHeld

    No blocking poll. No is_holder_stale probe. No RefresherThread. No --hold mode.
    claim.py must NOT import: typer, multiprocessing, subprocess, threading (no hold runner).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → claim_take() | Caller provides area name and reason; both are validated but are caller-controlled strings |
| env → session_id | CLAUDE_CODE_SESSION_ID is caller-environment-controlled; an attacker could spoof any session_id value |
| Lua scripts → Redis HASH | Lua compares session_id + project_hash before modify/delete; these are string comparisons, not cryptographic proofs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-01-01 | Spoofing | session_id in claim_take | accept | session_id from CLAUDE_CODE_SESSION_ID is env-level; spoofing requires env control which is equivalent to process control. No stronger identity is in scope for M1. |
| T-4-01-02 | Tampering | LUA_CLAIM_REFRESH_OR_TAKE | mitigate | Lua compares both session_id AND project_hash before refresh. A caller can only refresh if they know (and can reproduce) both values — project_hash is deterministic from cwd, not user-supplied. |
| T-4-01-03 | Tampering | LUA_CLAIM_COMPARE_AND_DELETE | mitigate | Same dual-field check: session_id + project_hash must match before DEL. Non-holder release exits 3, not 0. |
| T-4-01-04 | Elevation of privilege | Anonymous claim_take | mitigate | resolve_session_id() always returns a non-empty string (pid- fallback); the anonymous-refusal gate is at the verb layer (Plan 04-02), not here. claim.py itself never suppresses the pid- fallback — it is the verb's job to detect "no CLAUDE_CODE_SESSION_ID" and error before calling claim_take. |
| T-4-01-05 | Denial of Service | TTL exhaustion via infinite refresh | mitigate | MAX_TTL = 86400 caps the Redis EXPIRE argument. The Lua script enforces that only the holder can refresh — a third party cannot extend a claim indefinitely. |
</threat_model>
