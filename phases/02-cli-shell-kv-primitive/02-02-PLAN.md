    - `emit_ok(data: dict | list | None = None, *, json_mode: bool | None = None) -> NoReturn`:
      - In JSON mode: writes `json.dumps({"schema_version": "1", "status": "ok", "data": data})` to stdout with trailing newline (D-04), then `raise SystemExit(0)`
      - In TTY mode: if `data` is a dict with simple scalar values, render as readable plain text (e.g., `key: value\n`); if `data` is `{"keys": [...]}` render one key per line; if `data is None` print nothing; else `print(repr(data))`. Then `raise SystemExit(0)`.
    - `emit_not_found(message: str, *, json_mode: bool | None = None) -> NoReturn`:
      - In JSON mode: writes `json.dumps({"schema_version": "1", "status": "not_found", "error": {"code": "not_found", "message": message}})` to stdout with newline, then `raise SystemExit(2)`
      - In TTY mode: writes the literal `message` to stderr with newline, then `raise SystemExit(2)`
    - `emit_error(code: str, message: str, *, json_mode: bool | None = None) -> NoReturn`:
      - In JSON mode: writes `json.dumps({"schema_version": "1", "status": "error", "error": {"code": code, "message": message}})` to STDERR (errors go to stderr per PROJECT.md) with newline, then `raise SystemExit(1)`
      - In TTY mode: writes `f"em-proj: error: {message}"` to stderr with newline, then `raise SystemExit(1)`
  </behavior>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| verb code → output.py | Verb functions pass `data` dicts and error strings into emit_*; output.py must not trust the call site to have escaped values (it serializes via `json.dumps` which handles escaping) |
| output.py → stdout/stderr | The TTY-vs-non-TTY decision controls whether structured JSON is emitted; an incorrect default could leak machine-readable JSON into a human terminal log |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-02-01 (T-2-05 TTY hijack from context) | Tampering | `resolve_json_mode` default | mitigate | `json_mode=None` defers to `sys.stdout.isatty()`; non-TTY → JSON (machine-safe default per CONTEXT T-2-05). `--no-json` is the explicit human-override path; tested in Task 2. |
| T-2-02-02 (Tampering via raw data) | Tampering | `emit_ok` data argument | mitigate | All structured output flows through `json.dumps(...)` which escapes embedded quotes and control characters. TTY-mode plain rendering uses Python `print()` which does not interpret shell metacharacters in the value. |
| T-2-02-03 (Information disclosure via error messages) | Information disclosure | `emit_error` message | mitigate | output.py does NOT inject file paths, env values, or Redis connection details — the caller is responsible for constructing a clean message. Documented in the module docstring; Plan 03/04 verb implementations honor it. |
| T-2-02-04 (Schema-version drift) | Tampering | `SCHEMA_VERSION` constant | mitigate | Locked as `"1"` (string literal per D-02) and asserted by `test_schema_version_is_literal_one`; bumping requires editing two places (module + test) which surfaces the change in review. |
| T-2-02-05 (Stderr/stdout confusion) | Information disclosure | success vs error routing | mitigate | Success → stdout (`emit_ok`); errors → stderr (`emit_not_found` TTY only, `emit_error` always). Tested in `test_emit_error_json_envelope_to_stderr` and `test_emit_not_found_tty_mode_writes_to_stderr`. |
</threat_model>
