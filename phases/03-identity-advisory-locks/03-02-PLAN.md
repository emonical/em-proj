<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Redis lock value → probe | The holder dict is untrusted JSON read from Redis; the probe must reject malformed input safely |
| OS process table → probe | psutil reads the kernel's process state; an adversary with same-UID privileges could spoof create_time via process injection (out of M1 threat model) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-02-01 | Tampering / false-positive stale | is_holder_stale displacing live holders | mitigate | All three probes are conservative on uncertainty: AccessDenied → "live" (return True for pid_alive, True for proc_start_matches), so we never displace a holder we can't fully read. The Lua compare-and-swap in Plan 03-03 is the second line of defense — if the holder JSON changes between our probe and our write, the swap no-ops. |
| T-3-02-02 | Tampering / false-negative stale | crashed holder not detected | accept | If psutil temporarily misreports (e.g., during a process-table refresh window), one acquire cycle may miss the stale signal. The TTL backstop (D-04: 60s default) recovers the lock within a minute. Phase 5's `/global-state unlock --force` covers the long-tail case. |
| T-3-02-03 | Spoofing | adversary forges holder dict in Redis | accept | M1 threat model is single-user, single-machine; only the current user can write to Redis (loopback bind + same UID). Phase 5 + Phase 6 expand the trust boundary. |
| T-3-02-04 | Information disclosure | error messages leak pid/process metadata | mitigate | `is_holder_stale` returns a bool — no error string. `ValueError` for malformed input names only the missing key (not the rejected pid value), echoing the kv.py ValidationError discipline. |
| T-3-02-05 | DoS via probe under contention | many acquire attempts each spawn psutil calls | accept | psutil.Process() is < 1ms per call on macOS/Linux; under the worst-case M1 contention (a few sessions retrying) the probe cost is negligible. Phase 5 may add caching if needed. |
| T-3-02-06 | Clock skew | proc_start_epoch float comparison | mitigate | `PROC_START_EPSILON = 0.5` seconds — well above clock-jitter (nanoseconds) and well below realistic process-start gaps. Documented in the module constant. |
</threat_model>
