# Milestone v1.0: em-proj state primitive

**Status:** ✅ SHIPPED 2026-06-07
**Phases:** 1-7
**Total Plans:** 30
**Timeline:** 2026-05-16 → 2026-06-01 (~16 days)

## Overview

Bootstrapped `em-proj` as an installable Python CLI and proved the `state`
primitive end-to-end: a Redis-backed coordination layer that lets any Claude
Code session or sub-agent ask "is it safe to edit X, or is someone else working
there?" and get a structured, parseable answer grounded in current cross-session
reality.

The build order followed TDD-first discipline (multi-process harness before any
locking code), then layered the primitive: KV → identity → advisory locks →
long-lived claims → skill surface → first validating consumer (gsd-sdk
workstream) → project-scoped reservation registry for cross-clone coordination.

## Milestone Summary

**Key Decisions:**
- Backend = persistent Redis (not flat-files/SQLite) — future milestones (session registry, messaging, handoff) want pub/sub + keyspace notifications + TTL natively. ✓ Good
- Stack = Python 3.12+ via uv — readability for long-lived personal tooling; `uv tool install` solves distribution. ✓ Good
- Top-level namespace = `em-proj` (new CLI, not extending gsd-sdk) — avoids collision with gsd-sdk's `state.*` family. ✓ Good
- Lock default = block-with-1s-timeout, `--warn` opt-in — safe default at the SDK callsite; "advisory-warn becomes theater". ✓ Good
- Claim model added to M1 alongside lock — the real M1 use case (workstream pointer) is a claim, not a lock. ✓ Good
- Multi-process test harness as first deliverable — single-process tests give false confidence with advisory locking. ✓ Good
- gsd-sdk integration via shell-out, not source extension — keeps em-proj independent of gsd-sdk's release cycle/language. ✓ Good
- Phase 7 RESERVE group added as an M1 extension — upstream-identity namespace for cross-clone coordination, disjoint from per-clone claims. ✓ Good

**Issues Resolved:**
- RESEARCH Open Question #1 (Redis 8.4 split-AOF under `appendonlydir/`) resolved during Phase 1
- Phase 4/5 code-review fix passes (CR + WR series) hardened error paths and stale-filter races before phase close

**Technical Debt / Notes:**
- gsd-sdk consumer patch (Phase 6) edits the npm-installed `workstream.js`/`workstream.ts` directly; a structural xfail-on-reversion test guards against silent upstream overwrite, but the patch must be re-applied if gsd-sdk is reinstalled.
- Stray `worktree-agent-*` branches + one locked agent worktree accumulated during parallel execution (known agent-worktree pile-up hazard) — left for separate cleanup.
