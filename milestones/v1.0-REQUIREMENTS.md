# Requirements Archive: em-proj v1.0

**Archived:** 2026-06-07 (milestone v1.0 shipped)
**Defined:** 2026-05-17
**Core Value:** A sub-agent, skill, or session can ask the substrate "is it safe to edit X, or is someone else working there?" and get a structured, parseable answer grounded in current cross-session reality.

> All v1 requirements below shipped and were verified across Phases 1-7
> (see `.planning/milestones/v1.0-ROADMAP.md` and each phase's VERIFICATION.md).

## v1 Requirements — all complete ✓

### CLI — em-proj CLI shell
- [x] **CLI-01**: Installable via `uv tool install em-proj` from local source
- [x] **CLI-02**: Subcommand dispatch via `em-proj <subcommand> <verb> [args...]` (typer)
- [x] **CLI-03**: `--help` available for every subcommand and verb
- [x] **CLI-04**: Semantic exit codes — 0 success / 1 error / 2 not-found-or-not-held / 3 held-by-another
- [x] **CLI-05**: Machine-readable JSON when stdout is not a TTY OR when `--json` is passed; output includes a `schema_version` field; errors go to stderr

### KV — `em-proj state` key/value operations
- [x] **KV-01**: User can `em-proj state get | set | del | list` with atomic write semantics
- [x] **KV-02**: User can set a TTL on any write via `em-proj state set --ttl <seconds>`

### LOCK — short-lived advisory locks
- [x] **LOCK-01**: User can `em-proj state lock <name>` and `unlock <name>` (process-scoped)
- [x] **LOCK-02**: `lock` blocks with a 1-second timeout by default; `--warn` flag opts into warn-mode
- [x] **LOCK-03**: User can `em-proj state lock --hold <name> -- <cmd...>` to auto-acquire, run, and auto-release on exit

### CLAIM — long-lived area claims
- [x] **CLAIM-01**: User can `em-proj state claim <area> [--ttl <secs>]` (default 30min, refreshable) and `release <area>`
- [x] **CLAIM-02**: User can `em-proj state check <area>` to see holder metadata `{session_id, project_hash, reason, claimed_at, expires_at}`
- [x] **CLAIM-03**: Claims refuse anonymous holders by default — session-id must be resolvable or the call errors with exit 1

### REDIS — persistent Redis backend
- [x] **REDIS-01**: System runs against a loopback Redis configured with `appendonly yes`, `appendfsync everysec`, `save 900 1`; managed via `brew services`
- [x] **REDIS-02**: `em-proj state` commands emit a clear, actionable error when Redis is unreachable (no cryptic connection traces)

### IDENT — identity, namespacing, stale-detection
- [x] **IDENT-01**: Session-id resolved from `CLAUDE_CODE_SESSION_ID` with a documented fallback chain; project-hash derived from `$PWD` (git-toplevel fallback) via `tr '/' '-'`, matching `~/.claude/projects/<hash>/`
- [x] **IDENT-02**: Stale detection uses a composite `{pid, proc_start_epoch, boot_id}` with TTL as the final backstop

### SKILL — `/em-global-state` Claude skill
- [x] **SKILL-01**: User (or sub-agent) can run `/em-global-state list`, `get <key>`, `locks [--mine|--stale]`, `claims [--mine|--active|--stale]`
- [x] **SKILL-02**: User can run `/em-global-state unlock|release [--force]` as an escape hatch, with confirmation when a live holder exists
- [x] **SKILL-03**: Skill output is parseable by sub-agents (stable schema, no ad-hoc formatting)

### CONSUMER — first validating consumer
- [x] **CONSUMER-01**: `gsd-sdk workstream.set` writes through `em-proj state claim` via shell-out (no source extension of gsd-sdk)
- [x] **CONSUMER-02**: Two concurrent Claude Code sessions in the same project no longer silently clobber each other's active-workstream pointer (demonstrated end-to-end)

### RESERVE — project-scoped reservation registry (cross-clone coordination)
- [x] **RESERVE-01**: Reservations namespace by a stable `upstream_identity` derived from `git remote get-url origin`, distinct from per-clone `project_hash`
- [x] **RESERVE-02**: Holder dict auto-stamps `workstream` (from the caller's `workstream.active` claim) → `{session_id, project_hash, upstream_identity, workstream, reason, claimed_at, expires_at}`
- [x] **RESERVE-03**: `/em-check-state` (no args) auto-resolves `upstream_identity` from cwd's origin and returns all reservations grouped by category prefix
- [x] **RESERVE-04**: `/em-check-state --category <name>` filters to one category; `--upstream <url-or-identity>` overrides cwd resolution
- [x] **RESERVE-05**: `em-proj state reserve <category>.<resource> [...]` sugar over `claim`; unset workstream → TTY prompts, non-TTY exits 1, no silent fallback

### TEST — multi-process test harness
- [x] **TEST-01**: A multi-process test harness spawns `fork+exec`'d children and races them at the `em-proj` CLI boundary
- [x] **TEST-02**: The harness landed as the first M1 deliverable, before any locking or claim code (TDD-first)
