<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env-var → identity | `CLAUDE_CODE_SESSION_ID` is user-controlled; reaches the lock-record JSON via `current_process_composite` |
| cwd → identity | `os.getcwd()` reflects the calling process's shell state; reaches `project_hash` field of lock records |
| psutil → identity | OS process table contents are read into the lock record (pid, proc_start_epoch, boot_time) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-01-01 | Spoofing | resolve_session_id | accept | session_id is informational; locks bind to pid + proc_start_epoch + boot_id for actual ownership (D-02 + D-06 compare-and-delete). A spoofed CLAUDE_CODE_SESSION_ID env var changes the displayed holder but cannot unlock another process's lock. |
| T-3-01-02 | Information disclosure | current_process_composite | mitigate | Returned dict carries only project-hash (already encoded in the cwd path the user typed) and PID; no env-var dump, no file-path leak beyond cwd-as-hash. Identity helpers never log secrets. |
| T-3-01-03 | Tampering | resolve_project_hash via PATH-controlled git | mitigate | If the function shells out to `git rev-parse --show-toplevel`, use `subprocess.run([...], shell=False, timeout=2)` with an absolute git path resolved once via `shutil.which`, OR (preferred) skip the git fallback entirely for Phase 3 and use `os.getcwd()` only. Document the choice. |
| T-3-01-04 | DoS via long path | resolve_project_hash | accept | A pathologically long cwd produces a long hash string; Redis lock keys remain bounded (`state:lock:<name>` is keyed by lock name, not project hash). The composite dict ends up large but is not a DoS vector. |
| T-3-01-05 | Privilege via psutil | current_process_composite | accept | `psutil.Process()` on the current pid never raises AccessDenied; `psutil.boot_time()` is read-only OS info. No elevation. |
</threat_model>
