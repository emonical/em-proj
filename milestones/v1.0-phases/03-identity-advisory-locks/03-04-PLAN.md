```python
    json_flag: Annotated[bool | None, typer.Option("--json/--no-json", help=_JSON_HELP)] = None,
) -> None:
    """Acquire a short-lived advisory lock.

    Without flags: blocks up to 1s, exits 3 if still held.
    --warn (TTY only): prompts for human override on held lock.
    --hold -- <cmd>: auto-acquire, run <cmd>, auto-release on exit.
    """
    # 1. Mutual-exclusion check (D-08) BEFORE any Redis call.
    # 2. Resolve json_mode.
    # 3. If --hold: dispatch to lock_hold_run stub (Plan 03-04: emit_error('not_implemented', ...); Plan 03-05 replaces with real dispatch).
    # 4. get_client + die_if_redis_unreachable.
    # 5. Try lock_acquire; on HeldByAnother + not warn: emit_held_by_another, exit 3.
    # 6. On HeldByAnother + warn + TTY: prompt; on y: call lock_force_displace + emit_ok with stderr warning; else exit 3.
    # 7. On HeldByAnother + warn + non-TTY: emit_error("warn_requires_tty", ...) exit 1 (per D-07).
    # 8. On success: emit_ok with holder subset.
```

**CLI option order convention (Warning #5 pin — applies to all subsequent tests):**

Click parses options BEFORE positionals before the `--` separator. Canonical order:

```
em-proj state lock [--ttl N] [--reason "x"] [--warn|--hold] [--json|--no-json] <name> [-- <cmd...>]
```

Examples:
- `em-proj state lock foo` — bare acquire
- `em-proj state lock --ttl 30 foo` — TTL override
- `em-proj state lock --warn foo` — warn flow on a held lock
- `em-proj state lock --hold foo -- sleep 5` — hold-and-wrap (Plan 03-05; stub here)
- `em-proj state lock --ttl 2 --hold ttl-foo -- sleep 3` — full form

Document this order convention in the verb docstring so subsequent tests and downstream tooling stay consistent.
